# GLog-Front 요구사항 정의서

> v1.0 · 2026-10-02 · 1단계(요구사항 분석) 산출물
> 기준 문서: 기능명세서 v1.9 · 화면설계서 v0.7 · DB명세서 v0.4 · 목업 v2 (모두 `/Users/handong-gwan/동아리 프로젝트/`)
> 근거 분석: `docs/analysis/A1~A5` (화면·라우트 / 도메인 규칙 / API 계약 / 디자인 시스템 / 범위·위험·수용 기준)
> 계약: `docs/api/schema.graphql` (v0.1)

이 문서는 구현의 기준이다. 세부 근거와 표 전체는 분석 문서에 있고, 여기에는 **결정된 것**만 적는다. 명세에 근거가 없는 결정은 **(제안)**, 명세 취지에서 도출만 한 것은 **(추측)** 이다.

## 1. 목표와 범위

### 1-1. 목표

1. 잔디로그 **웹 프론트엔드**를 목업 v2와 화면설계서 v0.7대로 구현한다.
2. 백엔드(Spring Boot + Spring for GraphQL)가 아직 없으므로 **목(mock) API로 전 화면이 동작**해야 한다.
3. **나중에 실제 백엔드로 바꿀 때 화면 코드를 한 줄도 고치지 않는다.** 바뀌는 곳은 설정과 어댑터뿐이다.
4. 앱(React Native)은 범위 밖이지만, GraphQL 문서(쿼리 · 뮤테이션)와 상태 라벨 매핑은 앱이 재사용할 수 있게 화면 코드와 분리한다.

### 1-2. 백엔드 교체 대비 요구 (S-1 ~ S-9)

| # | 요구 | 확인 방법 |
|---|---|---|
| S-1 | **계약 우선.** `docs/api/schema.graphql` 한 파일이 목과 실서버의 공통 계약이다 | 모든 operation을 SDL로 검증(codegen·CI) |
| S-2 | 화면은 생성된 타입·훅과 도메인 API만 쓴다. `fetch` · 목 · Apollo 링크를 직접 부르지 않는다 | lint 규칙 |
| S-3 | 목은 **네트워크 계층**에서 GraphQL과 REST(multipart) 둘 다 흉내 낸다 | 설정 하나(`VITE_API_MODE`)로 전환 |
| S-4 | 오류는 `extensions.code ?? classification`으로 읽어 도메인 코드로 정규화한다. `message`는 화면에 쓰지 않는다 | 단위 테스트 |

| S-7 | 비공개 팀 이름은 **서버가** 가린다. 목도 똑같이 가린다 | 응답 검사 |
| S-8 | 재계산을 일으키는 조작(정정·소급 면제·경고 복구·이행 체크·개인 면제 승인) 뒤에는 부분 패치 대신 **재조회** | 수용 기준 |

### 1-3. 만들지 않는 것

임시저장(localStorage 초안 포함) · 전역 검색 · 헤더 자동완성/최근 검색어/건수 · 알림·폴링(AU-03 승인 확인도 버튼 재조회) · 관리자 행동 로그 화면 · 통계·랭킹·인기순 정렬 · 앱 화면 · 다크 모드 · **판정·경고를 프론트에서 계산하는 것**(5장).

### 3-2. 라우트 트리

```
RootLayout                 세션 · Apollo · 토스트 · 확인 다이얼로그 · 스크롤 복원 · 전역 오류 화면(CM-02)
├─ PublicOnly ─ BareLayout     /login                       AU-01
├─ BareLayout                  /auth/callback               AU-02
├─ PendingOnly ─ BareLayout    /pending                     AU-03 (대기 · 거절)
├─ RequireActiveMember ─ AppLayout   공통 헤더 · 드로어 · `/` 단축키 · 본문 오류 경계(E-51)
│   ├─ /  /weekly  /warnings
│   ├─ /teams  /teams/new  /teams/join  /teams/invitations
│   ├─ /teams/:teamId ─ TeamScope        (index) TM-05 · manage TM-06 · exemption TM-08 (RequireTeamLeader)
│   ├─ /posts  /posts/new  /posts/:postId  /posts/:postId/edit
│   ├─ /notices  /notices/:noticeId
│   ├─ /profile/me  /profile/edit  /profile/:userId
│   ├─ /admin ─ RequireAdmin ─ AdminLayout   (index) · warnings · members · exemptions · notices · posts · *
│   └─ *                        CM-02 404 (헤더 유지)
└─ *                            비로그인: 알려진 보호 경로 → /login, 미지 경로 → Bare 404
```

- **React Router 데이터 라우터**(`createBrowserRouter`)를 쓴다 — 이탈 확인(E-26), 라우트 오류 화면(CM-02), 스크롤 복원 때문이다.
- `/admin/:tab` 동적 파라미터 대신 **자식 라우트 5개를 명시**한다. 탭별 코드 분할이 되고, 잘못된 탭이 404로 떨어진다.
- 정적 경로(`/teams/new` · `/posts/new` · `/profile/me` · `/profile/edit`)가 동적 경로보다 먼저 매칭된다.
- **경로 · 쿼리는 한 모듈의 빌더 함수로만 만든다** — `paths.posts({ type, q, tag })`. 헤더 검색 · 드로어 · BD-01 · TM-05 · PR-01이 같은 계약을 쓴다.
- URL은 소문자(`troubleshooting`), API enum은 대문자(`TROUBLESHOOTING`) — 변환은 빌더 한 곳에서.
- 경로 파라미터 형식: `teamId` · `userId` · `noticeId` = 양의 정수, `postId` = 24자리 hex. **형식이 틀리면 API를 부르지 않고 404.**
- **로그인 · 승인 확인 뒤 목적지는 항상 `/`** 이다(4-3). 원래 가려던 곳으로 돌려보내지 않는다.

### 3-3. 레이아웃

| 단위 | 화면 | 내용 |
|---|---|---|
| BareLayout | AU 계열 · 비로그인 404 | **로고만 있는 상단 바**(W-01) + 중앙 정렬 본문 |
| AppLayout | 로그인 후 전부 | 공통 헤더(☰ · 로고 · 검색창 · 사용자) + 오버레이 드로어 + 본문 폭 컨테이너(700 / 960 / 1120) |
| AdminLayout | AD-01 6개 URL | 제목 · 오늘 날짜 · **본문 가로 탭 6개 + 처리 대기 배지** |
| TeamScope | TM-05 · 06 · 08 | 레이아웃 없음. teamId 형식 검사 · 팀 조회 1회 · 내 역할 |

**드로어 구성 (M-09)**: 목업 W-03 그대로 — 홈 / 내 활동(주간 활동 · 내 경고·벌칙) / 팀(내 팀 목록 · 팀 만들기 · 팀 참가 · 받은 초대 + 건수 배지) / 게시판(트러블슈팅 · 개발일지) / 공지사항(공지 목록) / 프로필(내 프로필) + 하단 로그아웃. 여기에 **관리자에게만 "관리자" 그룹**(6개 + 처리 대기 배지)을 더한다. 드로어 본문은 스크롤된다(W-03의 잘림을 고친다).

**관리자 메뉴 (M-08)**: 드로어 "관리자" 그룹 **과** AdminLayout 본문 가로 탭 6개를 **둘 다** 둔다. 목업 v2(W-15·W-16)가 가로 탭이고, 확정 규칙은 "관리자 대메뉴는 관리자에게만 노출"이다.

## 4. 권한 · 라우트 가드

### 4-1. 세션 모델

세션은 `session.status ∈ ANONYMOUS | PENDING | REJECTED | ACTIVE` + `viewer { id, githubLogin, nickname, role(MEMBER|ADMIN) }`로 추상화한다. 화면은 이 값만 본다. 토큰이 어디 있는지, 대기 회원에게 토큰이 있는지는 세션 계층만 안다(C-01 — 11장 B-01).

### 4-2. 가드

| 가드 | 위치 | 통과 조건 | 실패 시 |
|---|---|---|---|
| PublicOnly | `/login` | ANONYMOUS | ACTIVE → `/` · PENDING/REJECTED → `/pending` |
| PendingOnly | `/pending` | PENDING · REJECTED | ACTIVE → `/` · ANONYMOUS → `/login` |
| RequireActiveMember | AppLayout | ACTIVE | ANONYMOUS → `/login` · PENDING/REJECTED → `/pending`(E-01 · E-02) |
| RequireAdmin | `/admin` 부모 **한 곳** | role = ADMIN | 본문 403(E-09) + [홈으로] |
| TeamScope | `/teams/:teamId` | **서버 응답** | FORBIDDEN → 403 · NOT_FOUND → 404. **관리자도 예외 없음** |
| RequireTeamLeader | manage · exemption | 팀 응답의 `viewerRole = LEADER` | 403. 위임 직후엔 TM-05로 replace |
| 글 수정 | `/posts/:postId/edit` 화면 안 | `viewerCanEdit` | 403 / 삭제된 글(E-31) |

- 가드는 **화면 진입마다** 세션을 읽는다(5-2-3). 클라이언트 가드는 1차 방어이고 최종 권한은 서버다.
- 403·404는 **URL을 그대로 두고 본문만** 대체한다.

### 4-3. 인증 흐름

`AU-01 [GitHub으로 로그인]` → 백엔드 `/oauth2/authorization/github` 로 브라우저 이동 → GitHub → 백엔드 콜백 → 일회용 코드와 함께 `/auth/callback?code=` 로 복귀 → `exchangeLoginCode(code)` → `AuthPayload { status, token, viewer }` → 상태에 따라 `/` · `/pending`.

- **토큰을 주소에 담지 않는다.** 주소에는 일회용 코드만 온다(기능명세서 1장).
- **StrictMode에서 교환이 두 번 나가면 두 번째가 E-05로 실패한다.** 같은 코드의 교환은 1회만 일어나게 막는다(진행 중인 Promise를 코드 단위로 캐시).
- 토큰은 `tokenStore` 인터페이스 뒤 localStorage에 둔다(FC-03). 401 또는 `UNAUTHENTICATED`면 토큰 폐기 → `/login` + 토스트 "로그인이 만료됐어요. 다시 로그인해 주세요."(E-03).
- 목 모드에서는 AU-01 버튼이 백엔드 대신 목 OAuth 화면 없이 바로 `/auth/callback?code=mock-<persona>` 로 보낸다.

## 5. 업무 규칙 — 프론트의 책임 경계

### 5-1. 프론트는 판정하지 않는다

서버 값으로 받아 **그리기만** 하는 것: 인증일 수(잔디 + 기록글을 KST 날짜로 합친 값) · 주간 상태 · 누적 경고 · 연속 통과 · 벌칙 대상 · 팀별 경고 · 기록글 인정(`isRecord`) · 비공개 팀 마스킹 · 권한 관계 · "통과 예정/아직" · 다음 차감까지 남은 주 · 끝난 주 여부(`inFinalizedWeek`).

프론트가 계산하는 것: 표시용 산술("3 − n일 더"), 게이지 칸 수, 주차 라벨, 갱신 기준 문구, 배너 1개 고르기, **입력 검증**(E-29 · E-30 · E-56 · E-61 ~ E-63), BD-04 ⑩ 실시간 안내(서버 `isRecord`가 최종).

### 5-2. 화면마다 다른 경고 수

| 화면 | 세는 것 |
|---|---|
| TM-05 팀 현황판 | **그 팀 카테고리가 붙은 경고만.** 벌칙 대상 배지를 넣지 않는다(다른 팀 정보 유출 방지) |
| PR-01 ⑨ 팀별 경고 | 팀별 **중복 집계** + 안내문 "경고 1개에 여러 팀이 함께 붙을 수 있어서, 팀별 합계는 누적 경고 수와 다를 수 있어요." |
| CM-01 · PR-01 ⑧ · AC-02 · AD-01 | 사람 단위 누적. 모두 같은 값 |

### 5-3. 표시 규칙

- **비공개 팀**: 글의 팀 이름표는 영역째 숨김 · PR-01 ⑨와 AC-02 ③은 "비공개 팀" 문자열 · PR-01 ⑫ 소속 팀 목록은 항목 제외. 실명이 보이는 곳은 본인 소속 목록·현황판·글쓰기 셀렉트·초대 카드와 AD-01 경고 복구·벌칙 탭뿐이다.
- **잔디 갱신 기준 문구 (M-15)**: "오늘 오전 6시 기준"을 고정 문자열로 넣지 않는다. 서버 `asOf`로 "오늘/어제/{M/D} 오전 {H}시 기준"을 만든다. 갱신 시각 06:00 자체가 명세상 (제안)이다.
- **"이번 주"와 오늘 날짜는 서버 `clock`** 으로 정한다. 브라우저 시계는 E-27 배너(일요일 23:30 이후)를 띄울 때만 쓴다.
- **팀 미소속 회원**(5-2-7): CM-01은 진행·경고 카드 대신 "팀에 참가해야 판정이 시작돼요" + [팀 만들기] [초대코드 입력].
- **진행 중인 주의 "미달"은 쓰지 않는다**: TM-05 상태는 통과 / 아직 / 제외. TM-01 ⑧ 요약은 **"통과 n · 아직 n"** 두 값만(M-06, 제안 — 목업 W-08의 "미달 0명"은 정의상 늘 0).
- **보류(HOLD) 회원 표시 (M-05)**: 관리자 화면은 "보류". 회원 화면(PR-01 ⑩ · AC-01 지난 판정)은 "**확인 중**" 배지 + E-32 문구 (제안 — 인수인계 확정 규칙 "보류 건은 관리자 대시보드에서만 보인다"와 맞춤).
- **CM-01 상태 배너**는 하나만: E-39 → E-32 → E-36 → E-46 순.

### 5-4. 문구 규칙 (5-2-8)

해요체 통일 · 한 문장 40자 이내 · 사용자 탓 금지 · 기술 용어(토큰·서버·API·401·GraphQL) 노출 금지 · 이모지 금지 · 제한은 숫자로.
표준형 4종: 권한 없음 "이 페이지에 들어올 권한이 없어요." + [홈으로] / 찾을 수 없음 "찾는 내용이 없어요. 삭제됐을 수 있어요." + [뒤로] / 서버 오류 "잠시 문제가 생겼어요. 조금 뒤에 다시 시도해 주세요." + [다시 시도] / 입력 검증 "{항목}을 입력해 주세요." 인라인.
표시 위치 4원칙: 입력 검증 → 인라인 · 가벼운 성공/실패 → 토스트(3초) · **되돌릴 수 없는 행동 → 확인 다이얼로그** · 화면 전체 불가 → 전체 화면 대체(본문만).

화면별 예외 처리 전수표는 `docs/analysis/A2-domain-rules.md` 7장(E-01 ~ E-63을 G 가드 / F 프론트 단독 / S 서버 오류 코드 / D 서버 상태값 / P 서버 미리보기로 분류).

## 6. API 계약 요약

### 6-1. 전송

| 항목 | 계약 |
|---|---|
| GraphQL | `POST {API_ORIGIN}/graphql` 하나 |
| REST | `POST {API_ORIGIN}/api/members/me/profile-image` (multipart, 5MB · jpg/png/webp) **1개뿐** |
| 인증 | `Authorization: Bearer <JWT>` (쿠키 없음) |
| 실시간 | 없음 (구독 · 폴링 없음) |

### 6-2. 규모

`schema.graphql` v0.1 = 타입 59 · input 9 · enum 20 · union 1 · scalar 2 · **Query 28 · Mutation 36**. 인수인계의 추정(신설 5 + CRUD 18)의 약 2.8배다 — 백엔드 일정에 영향(R-15).

### 6-3. 설계 원칙

1. 실명 팀(`Team`)과 마스킹 표기(`TeamLabel`, id 없는 값 객체)를 다른 타입으로 둔다 — Apollo 정규화 캐시에서 섞이지 않게.
2. 권한 판단은 서버 계산 필드(`viewerRole` · `viewerCanEdit` · `viewerCanDelete` · `viewerIsAuthor` · `canRetry` · `canCorrect`).
3. **예상할 수 있는 상태는 데이터로** 받는다: `GrassFetchStatus`(E-32 · E-08) · `PostLookup = Post | DeletedPost`(E-31) · `AuthPayload.status`(E-01 · E-02) · `LiveWeekStatus`.
4. 판정 규칙은 서버 한 곳(웹·앱이 두 번 구현하지 않게).
5. 스키마는 늘리기만 한다. 프론트는 **모르는 enum 값이 와도 깨지지 않는다**(숨김 처리).

### 6-4. 오류 코드 → 화면 처리

| 범주 | 도메인 코드 (`extensions.code`) | 화면 처리 |
|---|---|---|
| 인증 | `UNAUTHENTICATED` · HTTP 401 | 토큰 폐기 → `/login` + 토스트 (E-03) |
| 계정 상태 | `ACCOUNT_PENDING` · `ACCOUNT_REJECTED` | `/pending` (E-01 · E-02) |
| 권한 | `FORBIDDEN` · `TEAM_JOIN_BLOCKED` | 조회는 본문 403, 액션은 토스트 / 인라인 (E-09 · E-12) |
| 없음 | `NOT_FOUND` · `POST_DELETED` · `INVITEE_NOT_FOUND` · `TEAM_GONE` | 404 + [뒤로] / 삭제 안내 / 인라인 / 토스트 |
| 검증 | `VALIDATION_FAILED`(+`extensions.field`) · `LOGIN_CODE_INVALID` · `INVITE_CODE_NOT_FOUND` · `ALREADY_TEAM_MEMBER` · `LEADER_MUST_TRANSFER` · `LAST_MEMBER` · `EXEMPTION_DUPLICATE` · `JUDGMENT_NOT_CORRECTABLE` · `SYSTEM_NOTICE_UNDELETABLE` | 인라인 / 토스트 / 화면별 문구 |
| 충돌 | `PREVIEW_STALE` | 미리보기 재조회 + "다른 변경이 먼저 반영됐어요. 바뀐 결과를 다시 확인해 주세요." |
| 서버 | `RECALC_BUSY` · `INTERNAL` · HTTP 5xx | 표준 서버 오류 + [다시 시도] (E-52) |
| 네트워크 | 응답 없음 | **본문만 대체, 헤더·드로어 유지, 입력 내용 유지** (E-51) |

코드별 문구 전수: `docs/analysis/A3-api-contract.md` 7-2.

### 6-5. 목록 · 캐시

- **모든 목록은 커서 Connection(nodes + pageInfo + totalCount, first 20) + [더 보기]** — Q-06 확인 대기(11장 U-01). 목록 UI는 `usePagedList` 훅 하나로 감싸 방식이 바뀌어도 화면은 그대로다.
- 낙관적 갱신은 값 하나만 바뀌는 조작에만(공개 설정 토글 · 공지 고정 · 가입 승인 · 댓글 수정). 재계산 조작은 재조회(S-8).
- 기본 `errorPolicy: 'none'`. **CM-01만 `'all'`**(공지 실패가 진행 카드를 지우지 않게).

## 7. 디자인 시스템 요약

전체: `docs/analysis/A4-design-system.md`.

- **토큰 원천은 목업 v2** `:root` 변수 + 하드코딩 색 22개(아바타 6색 별도). v1(IBM Plex · `#1F7A4D`) 값을 가져오지 않는다. 주요 값: 브랜드 `#1E6B3C` · 잔디 5단계 `#E7ECE9 · #C0E3CD · #7FC49B · #3A9A5E · #1E6B3C` · 기록글 `#2A4AA8` · 위험 `#B42318` · 경고 `#9C4A0A` · 캔버스 `#F4F6F3`. 글꼴 Pretendard(대체 Noto Sans KR) · 글 본문 Noto Serif KR.
- **본문 폭 3종**: 700(팀 관리·글 상세·글쓰기) · 960(기본) · 1120(관리자).
- **브레이크포인트**: 768px(헤더 검색을 돋보기 버튼으로 접음) · 960px(관리자 2단 → 1단, 정정 패널은 순차 전환). 드로어는 모든 폭에서 같다.
- **시그니처 컴포넌트 `WeekStrip`**: 한 칸에 잔디 단계(배경 5단계) · 기록글(오른쪽 위 파란 모서리) · 인증일(밑줄 + 굵은 요일) · 오늘(진한 테두리) / 미래(점선). 크기 32 · 46 · 54. **지난 주차는 잔디 단계가 없으므로 단색(3단계)** 으로 그린다(M-17).
- **상태 배지는 색 + 아이콘 + 라벨 3중**. enum → 라벨 매핑은 `toBadge(domain, value, context)` 한 파일에 모은다(같은 FAIL이 PR-01은 "미달 (경고)", AC-01은 "미달").
- **목업 v2에 없는 컴포넌트**(토스트 · 확인 모달 2종 · 빈 상태 · 스켈레톤 · 전체 화면 상태 · 보류 배지)는 목업 v1 구조를 v2 토큰으로 다시 칠한다. 스피너는 AU-02에서만(E-54).
- **접근성 WCAG 2.1 AA 목표 (M-16)**: 입력·라디오·검색창 테두리를 `#87928B`(3.22:1)로, placeholder를 더 진하게. 스트립·히트맵 칸마다 스크린리더 텍스트. 포커스 링 `:focus-visible` 2px. 목업보다 테두리가 약간 진해진다.
- **"기록글 n개" 배지는 중립색 + 문서 아이콘 (M-19, 제안)** — 목업은 면제 배지와 같은 파랑이라 한 화면(W-06)에서 둘이 섞인다.
- 마크업: 텍스트 액션·스위치·입력은 실제 `<button>` · `<input>`으로(목업은 span/div).
