## 3. 공통 요소

### 3-1. 공통 헤더 · 헤더 검색 (§5-1-0-1 · §4-3)

| 항목 | 내용 |
|---|---|
| 적용 | 로그인한 회원(ACTIVE)의 **웹 전 화면**. AU 계열 · 비로그인 CM-02에는 없다 (§4-3, §5-1-0-1) |
| 구성 | ① ☰ 드로어 열기 · ② 로고 → `/` · ③ 검색창 · (세로선) · ④ 사용자 표시(아바타+닉네임) → `/profile/me` **(제안, §5-1-0-1 ④)** · ⑤ 제안 목록(팝업) · ⑥ 안내 줄 |
| 상태 | 닫힘(기본, 폭 약 290px, "`/` 를 눌러 글 검색") / 입력 중(약 470px, 초록 테두리, `Esc` 표시, 본문 옅게 가림) / 1자 입력(E-61 안내 한 줄) / 좁은 화면(<768px, 돋보기 버튼으로 접힘 **(제안)**) |
| ⑤ 제안 3줄 | ⓐ `{q} 트러블슈팅에서 검색` → `/posts?type=troubleshooting&q={q}` · ⓑ `{q} 개발일지에서 검색` → `/posts?type=devlog&q={q}` · ⓒ `#{q} 태그 글 모아보기` → `/posts?tag={q}`. 기본 선택 ⓐ, **BD-01 개발일지 탭을 보던 중이면 ⓑ** |
| 서버 호출 | **입력 중에는 없다** (자동완성 · 최근 검색어 · 건수 없음, 인수인계 9/30) |
| 키보드 | `/` 전역 단축키 — **input · textarea · contenteditable · 모달 내부 · IME 조합 중(`isComposing`)에서는 가로채지 않는다** (E-62). ↑↓ 이동 · Enter 실행 · Esc 닫기. 빈 칸 Enter 무동작 |
| 검색어 규칙 | trim · 2자 이상(E-61) · 50자 차단(E-63 제안) — BD-01 ③과 동일 |
| 접근성 | `role="search"`, ⑤ `listbox`, `/`는 "슬래시 키로 글 검색"으로 읽힘 **(제안)** |
| 목업 | W-02(닫힘) · W-04(입력 중) · W-05(결과) — **화면설계서와 일치** |
| 예외 | E-61 · E-62 · E-63 · E-51(결과 로딩 중 끊김 → BD-01 본문만 대체) |
| 앱 메모 | **앱에는 없다.** 같은 BD-01 검색 쿼리를 앱 게시판 탭 ③이 쓴다 |

### 3-2. 드로어 (§4-3 · §4-1-1 · W-03)

| `/profile/me` · `/profile/edit` | 프로필 > 내 프로필 (`/profile/:userId` 타인은 강조 없음) |
| `/admin/**` | 관리자 > 해당 |

> "회원 메뉴 '내 경고 · 벌칙'과 관리자 메뉴 '경고 복구 · 벌칙'은 다른 화면이다 … 이름과 아이콘을 반드시 다르게 둔다" (§5-1-10 공통 골격 주석). 드로어에 둘이 함께 보이므로 지킨다.

## 5. 라우트 설계 제안

### 5-1. 라우트 트리 **(제안)**

```

├─ PublicOnlyGuard ── BareLayout
│   └─ /login                         AU-01
├─ BareLayout
│   └─ /auth/callback                 AU-02   (가드: ACTIVE 세션이면 / 로)
├─ PendingOnlyGuard ── BareLayout
│   └─ /pending                       AU-03   (거절 안내 상태 포함 — §7 C-09)
├─ RequireActiveMember ── AppLayout   ← 공통 헤더 · 드로어 · `/` 단축키 · 본문 ErrorBoundary
```

- `/admin/:tab` 동적 파라미터 대신 **자식 라우트 5개를 명시**한다 **(제안)** — 탭별 코드 분할(§4-2 "코드 분할을 위해 URL을 나눴다")과 잘못된 탭 404가 자연스럽다.
- `/teams/new` · `/teams/join` · `/teams/invitations`, `/posts/new`, `/profile/me` · `/profile/edit`는 **정적 경로가 동적 경로보다 우선**해야 한다. React Router v6는 순위로 처리하지만, 경로 상수 표에 명시해 둔다.
- 비로그인 상태의 미지 경로: §5-2-3은 "비로그인은 그 외 경로 접근 시 AU-01로", §5-1-0-1은 "비로그인 상태의 CM-02(헤더 없음)"를 함께 말한다. **알려진 보호 경로 → `/login`, 미지 경로 → Bare CM-02 404 (제안).**
- 로그인 후 원래 가려던 곳으로 돌려보내는 규칙은 명세에 없다. `/login` 진입 시 원래 경로를 **sessionStorage**에 두고 AU-02 완료 후 복귀 **(제안)** — OAuth 왕복이 백엔드를 거치므로 라우터 state로는 유지되지 않는다. 명세의 "로그인 완료 → CM-01"(§4-3)과 충돌하므로 **도입 여부는 팀 합의 필요.**

- PR-02는 경로에 대상 id가 없어 가드가 필요 없다(§7 C-14).

| 잔디 인정 규칙 공지 식별(`is_system`) | AU-01 ⑤ · CM-01 ⑥ E-39 [설정 방법] | DB 1-15 |
| BD-01 탭별 결과 수(q · tag 있을 때) | BD-01 ① · 검색 결과 없음 상태 | §5-1-6 ① (제안) |

### 8-2. 오류 분류 → 화면 처리 (한 곳에서 매핑, 제안)

| 서버 오류 분류 (Spring for GraphQL `ErrorType` 기준 추측) | 화면 처리 | 예외 |
|---|---|---|
| UNAUTHORIZED (토큰 만료 · 무효) | 토큰 폐기 → `/login` + 토스트 "로그인이 만료됐어요. 다시 로그인해 주세요." | E-03 |
| FORBIDDEN | 본문 대체 "이 페이지에 들어올 권한이 없어요." + [홈으로] | E-09 |
| NOT_FOUND | 본문 대체 404 | E-53 |
| **삭제된 글 (별도 코드 필요)** | "삭제된 글이에요." + [목록으로], 댓글 숨김 | E-31 · EX-BD04-02 |
| BAD_REQUEST + 필드 정보 | 인라인 오류 | E-10~E-12 · E-15 · E-16 · E-29 · E-47 등 |
| 네트워크 단절 | 본문 대체 + [다시 시도], **입력 중 내용 유지** | E-51 |
| INTERNAL_ERROR | 본문 대체 또는 토스트 + [다시 시도] | E-52 |

> 비즈니스 오류(E-10 · E-11 · E-12 · E-17 · E-18 …)는 **화면 문구가 오류마다 다르므로 서버가 구분 가능한 코드를 줘야 한다 (제안).** 문구는 서버가 아니라 화면설계서 §5-4의 최종 문구를 프론트가 가진다(기술 용어 노출 금지, §5-2-8).

### 8-3. 목 단계 주의

- AU-01 ③ → 목 모드에서는 `/auth/callback?code=mock-{역할}`로 바로 보내 **회원 · 팀장 · 관리자 · 승인 대기 · 거절** 5가지 세션을 재현 **(제안)**.
- 목 데이터는 목업 v2 장면을 재현할 수 있어야 한다: 한동관(관리자 · A팀 팀장) · A팀 4명 · 비공개 팀 · 보류 0명/1명 이상 두 경우(⑧⑨ 표시 검증) 등.
