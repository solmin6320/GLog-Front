# 잔디로그 유스케이스 점검 결과 (2026-10-30)

로컬에서 실서버(백엔드 8080)와 화면(5180)을 연결해 관리자 계정과 테스트 회원 1명으로 기능을 직접 써 보며 찾은 오류와 개선점이다. 테스트로 만든 팀·글·댓글·회원은 점검 뒤 지웠다.

- 점검한 유스케이스: 27개
- 정상 13 · 일부 문제 4 · 막힘·가짜 10
- 할 일: 백엔드 10건 · 프론트 18건

"가짜"는 화면이 아직 서버에 연결되지 않아 브라우저 안 임시 데이터로 돌아간다는 뜻이다. 지금은 그 데이터를 비워 두어 빈 화면으로 보인다.

## 2. 백엔드가 할 일

우선순위: **높음** = 막힌 기능·데이터 오류, **중간** = 동작은 하지만 틀리거나 불편, **낮음** = 정리·문서

| # | 우선순위 | 할 일 | 내용 |
|---|---|---|---|
| B1 | 높음 | 로컬 브랜치와 원격 main 맞추기 | 원격 main에 가입 승인 폐지(#70)·관리자 지정(#71)이 이미 머지됐다. 로컬 `feature/open-signup-admin-promotion`(가입 즉시 활성·승격·정지·커밋 삭제·1년 잔디·시스템 공지 끄기)은 커밋 전이라 겹친다. main 기준으로 다시 맞춘 뒤 PR. |
| B2 | 높음 | 프로필 사진 업로드 API | 화면은 `POST /api/members/me/profile-image`(5MB, jpg·png·webp)로 올리는데 서버에 없다(S3 보류). 구현하거나 보류를 확정해 프론트에 알린다. |
| B3 | 중간 | 판정 안 된 지난 주 값 맞추기 | `myWeeklyActivity`로 지난 주를 보면 날짜별 잔디는 오는데 인증일은 0일로 온다. 같은 응답 안의 값이 서로 다르다. |
| B4 | 중간 | 팀 이번 주 요약에 제외 인원 추가 | `weekSummary`가 통과·미달·아직만 준다. 첫 참가 주나 면제 주인 팀원은 어디에도 안 세서 "통과 0명 · 아직 0명"인데 팀원은 2명으로 보인다. |
| B5 | 중간 | 새 회원의 1년 잔디 | 1년치는 매일 새벽 6시에만 채워진다. 가입한 날에는 프로필에 2주치만 보인다. 첫 로그인 때 한 번 불러오기를 검토. |
| B6 | 중간 | 가입 승인 폐지 뒤 남은 API 정리 | `approveMember`·`rejectMember`·`revertMemberToPending`과 승인 대기·거절 필터, 대시보드 "승인 대기" 숫자를 남길지 결정. |
| B7 | 낮음 | 테스트가 로컬 .env를 읽는 문제 | 로컬 `.env`에 `SESSION_COOKIE_SECURE=false`가 있으면 세션 쿠키 테스트 2개가 실패한다. 테스트 프로필에서 `.env`를 읽지 않게. |
| B8 | 낮음 | 오류 코드 이름 맞추기 | 서버 `TEAM_CODE_NOT_FOUND`·`TEAM_ALREADY_JOINED`와 화면 계약 `INVITE_CODE_NOT_FOUND`·`ALREADY_TEAM_MEMBER`가 다르다. 지금은 화면 쪽에서 바꿔 읽는다. |
| B9 | 낮음 | 시스템 공지 자동 생성 끈 것 기록 | "잔디 인정 규칙" 공지를 기동 때 만들지 않도록 바꿨다(`jandilog.notice.system-auto-create`). 명세에는 "삭제 불가 시스템 공지"라 결정표에 남긴다. |
| B10 | 낮음 | 바뀐 규칙 명세 반영 | 가입 즉시 활성, 관리자 승격, 회원 정지, 관련 커밋 삭제, 프로필 1년 잔디를 기능명세서·CLAUDE.md 결정표에 적는다. |

## 3. 프론트가 할 일

| # | 우선순위 | 할 일 | 내용 |
|---|---|---|---|
| F1 | 높음 | 남은 화면을 서버에 연결 | 팀 관리·나가기·삭제·개인 면제 요청, 공지 목록·상세·관리, 내 경고·벌칙, 관리자 대시보드(판정·정정·보류 재시도)·경고 복구·벌칙·면제·게시물 관리. 서버 API는 대부분 있다. 끝나면 가짜 데이터 코드를 지운다. |
| F2 | 높음 | 연결 전까지 가짜 저장 막기 | 관리자 공지 작성처럼 저장된 척하고 사라지는 동작이 가장 헷갈린다. 연결 전 화면은 "준비 중"으로 표시하고 버튼을 막는다. |
| F3 | 높음 | 768~1150px에서 헤더가 넘침 | 1024px 화면에서 헤더가 1150px(검색창을 펼치면 1332px)이라 페이지 전체가 가로로 밀린다. 중간 폭에서는 메뉴를 아이콘만 남기고 검색창을 아이콘 버튼으로 줄인다. |
| F4 | 중간 | 브라우저 탭 제목 | 공지·게시판·글쓰기·글 상세·글 수정 화면이 탭 제목을 바꾸지 않아 이전 화면 제목이 남는다. 글 상세는 글 제목으로. |
| F5 | 중간 | 관리자가 남의 글·댓글 지우기 | 상세 화면에 작성자만 삭제 버튼이 보인다. 관리자면 `adminDeletePost`·`adminDeleteComment`로 지울 수 있게. |
| F6 | 중간 | 모바일 표를 카드로 | 375px에서 팀 현황판은 기록글·경고·상태가, 관리자 회원 목록은 가입일·권한이 가로 스크롤 뒤에 숨는다. 사람별 카드(이름·상태 배지·7칸)로. |
| F7 | 중간 | 헤더 검색 결과 탭 | 항상 트러블슈팅 탭으로 열려 개발일지에만 결과가 있으면 "0건"부터 보인다. 결과가 있는 탭으로 연다. |
| F8 | 중간 | 가입 승인 폐지 잔재 | 대시보드 "승인 대기" 카드, 회원 탭의 승인 대기·거절 필터, 승인 대기 화면 문구를 정리한다(B6 결정과 함께). |
| F9 | 중간 | 내 팀 목록 요약 숫자 | 제외 인원을 함께 보여 "통과 0 · 아직 0"인데 팀원 2명으로 보이는 혼란을 없앤다(B4 뒤). |
| F10 | 중간 | 지난 주 주간 활동 표시 | 7칸 그림과 표가 같은 값을 쓰게 맞춘다(B3과 함께). |
| F11 | 중간 | 프로필 사진 버튼 | 서버 업로드가 생기기 전까지 "사진 바꾸기"를 숨기거나 준비 중으로(B2와 함께). |
| F12 | 낮음 | 로그인 화면 문구 | "첫 로그인 후에는 관리자 승인이 필요해요"를 지운다. |

| F14 | 낮음 | 태그 대소문자 | "Redis"로 입력하면 작성 중엔 #Redis, 저장 뒤엔 #redis. 입력 때부터 소문자로 보여 준다. |
| F15 | 낮음 | 경로 표시에 팀 이름 | 팀 현황판·팀 관리가 "홈 › 팀 › 내 팀 목록"으로 나온다. 팀 이름을 넣고, 없는 팀 404에서는 경로를 숨긴다. |
| F16 | 낮음 | 팀 현황판에서 이 팀으로 글쓰기 | 글쓰기는 `?team=`을 지원하는데 현황판에 버튼이 없다. |
| F17 | 낮음 | 남의 프로필 잔디 "다시 시도" | 눌러도 저장된 값을 다시 읽을 뿐이라 결과가 같다. 남의 프로필에는 안내 문구만. |
| F18 | 낮음 | 테스트를 실서버 기준으로 | 프론트 테스트 706개가 가짜 데이터로 돈다. 서버 연결을 마치면 실서버 계약 기준 테스트로 옮긴다. |

## 4. 점검 환경

- macOS 로컬, 백엔드 `GLog-Backend`(브랜치 `feature/open-signup-admin-promotion`, 커밋 전), 프론트 `GLog-Front-develop`(bridge 모드)
- 화면 폭: 1024px · 375px
- 실서버 GitHub 로그인은 앞서 사용자 계정으로 확인했고, 이번 점검은 개발용 로그인(`/__dev-login`)으로 진행했다.
